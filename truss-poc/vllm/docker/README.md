# vLLM sample — Docker build context (Truss `docker_server`)

Unlike the transformers sample, there is **no hand-written Dockerfile** here. The
image build context is **generated by Truss** from `../truss-model/config.yaml`
(`docker_server` backend), then two small AzureML adaptations are overlaid by
`../scripts/1-create-environment.sh`:

| # | Adaptation | Why |
|---|-----------|-----|
| 1 | Patch `proxy.conf`: `listen 8080` → `listen 5001` | AzureML always probes/scores on **5001**; Truss's nginx defaults to 8080 |
| 2 | Revert Truss's apt mirror rewrite (`mirror://mirrors.ubuntu.com/US.txt` → `archive.ubuntu.com`) | Truss points apt at community mirrors that 404 in the AzureML ACR build, failing `apt-get install nginx` |
| 3 | Add `vllm-launch.sh` + `COPY` it in the Dockerfile | Resolve the **mounted** model path and start vLLM (no baked-in weights) |

## What Truss generates (docker_server)

```
FROM vllm/vllm-openai:latest
  + nginx            (reverse proxy, patched to :5001)
  + supervisord      (init / process manager — replaces runit)
  ├─ program:model-server  → bash /app/vllm-launch.sh   (vLLM on :8000)
  └─ program:nginx         → nginx -g "daemon off;"     (proxy on :5001)
ENTRYPOINT supervisord
```

## nginx route mapping (Truss-generated)

| AzureML request | nginx rewrites to | vLLM endpoint |
|---|---|---|
| `GET /` | `/health` | liveness |
| `GET /v1/models/model` | `/health` | readiness |
| `POST /v1/models/model:predict` | `/v1/chat/completions` | Truss-native predict |
| `POST /v1/chat/completions` | *(passthrough)* | native OpenAI |
| `GET /v1/models`, `/v1/completions`, ... | *(passthrough)* | native vLLM |

## Files here
- `vllm-launch.sh` — vLLM startup; resolves the mounted model path, applies `VLLM_*` env vars. Mirrors the repo's `azureml-deployment-templates/templates/yaml/docker/vllm-run.sh` (but no runit).

The generated `.build-context/` (Dockerfile, `proxy.conf`, `supervisord.conf`,
`server/`, …) is git-ignored and rebuilt on every run.
